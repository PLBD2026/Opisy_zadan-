1. JAK KORZYSTAĆ Z PRZEWODNIKA
----------------------------------------------------------------------

Przewodnik pokazuje wszystkie konstrukcje potrzebne na laboratorium,
ale na innym przykładzie: wypożyczalni biblioteki (schemat katalog).
Każde polecenie uruchomiono w PostgreSQL 18.4, a komunikaty błędów
skopiowano z rzeczywistego wykonania.

Model przykładowy:

  wydawnictwo 1 ──< ksiazka >──< autor          (przez ksiazka_autor)
  regal       1 ──< egzemplarz >── 1 ksiazka
  czytelnik   1 ──< wypozyczenie >── 1 egzemplarz
  rezerwacja_sali                                (zakresy czasu)

  ──<  oznacza związek jeden do wielu (strzałka po stronie „wielu”)


2. RODZAJE WIĘZÓW INTEGRALNOŚCI
----------------------------------------------------------------------

  Więz         Co gwarantuje                        Uwagi
  -----------  -----------------------------------  ---------------------------
  NOT NULL     kolumna musi mieć wartość             tylko kolumnowy
  DEFAULT      wartość, gdy jej nie podano           formalnie nie jest więzem
  UNIQUE       brak powtórzeń (NULL może się         kolumnowy lub tablicowy
               powtarzać)
  PRIMARY KEY  UNIQUE + NOT NULL, jeden na tabelę    kolumnowy lub tablicowy
  FOREIGN KEY  wartość istnieje w tabeli             kolumnowy lub tablicowy
               nadrzędnej
  CHECK        warunek logiczny prawdziwy (albo      kolumnowy lub tablicowy
               NULL) dla każdego wiersza

Więz KOLUMNOWY zapisujesz przy definicji kolumny i dotyczy tylko tej
kolumny. Więz TABLICOWY zapisujesz po liście kolumn, po przecinku.
Więz obejmujący kilka kolumn (klucz złożony, CHECK porównujący dwie
kolumny) musi być tablicowy.

    CREATE TABLE przyklad (
        a integer CONSTRAINT pk_przyklad PRIMARY KEY,       -- kolumnowy
        b integer NOT NULL CONSTRAINT ck_przyklad_b CHECK (b > 0),
        c integer,
        CONSTRAINT ck_przyklad_bc CHECK (c IS NULL OR c > b) -- tablicowy
    );

Nazwa więzu: CONSTRAINT nazwa przed definicją więzu. Bez niej
PostgreSQL nada nazwę sam (np. ksiazka_rok_wydania_check). Własne nazwy
z przedrostkami pk_, fk_, uq_, ck_ czynią komunikaty błędów czytelnymi.


3. KOLEJNOŚĆ TWORZENIA I USUWANIA TABEL
----------------------------------------------------------------------

Tabela nadrzędna musi istnieć przed tabelą, która się do niej odwołuje
kluczem obcym. Usuwanie odbywa się w odwrotnej kolejności albo z opcją
CASCADE, która usuwa też więzy obce wskazujące na tabelę.

    -- skrypt, który można uruchamiać wielokrotnie
    DROP TABLE IF EXISTS wypozyczenie, czytelnik, egzemplarz, regal,
                         ksiazka_autor, autor, ksiazka, wydawnictwo CASCADE;

    SET search_path TO katalog;
    SELECT current_schema();          -- tu powstaną nowe obiekty


4. TABELE Z KLUCZAMI I WIĘZAMI – PRZYKŁADY
----------------------------------------------------------------------

4.1. Klucz główny podawany ręcznie, UNIQUE, DEFAULT, CHECK

    CREATE TABLE wydawnictwo (
        id_wydawnictwa smallint     CONSTRAINT pk_wydawnictwo PRIMARY KEY,
        nazwa          varchar(100) NOT NULL CONSTRAINT uq_wydawnictwo_nazwa UNIQUE,
        kraj           char(2)      NOT NULL DEFAULT 'PL'
                                    CONSTRAINT ck_wydawnictwo_kraj CHECK (kraj ~ '^[A-Z]{2}$')
    );


4.2. Klucz nadawany automatycznie, wzorzec, zakres wartości,
     klucz obcy kolumnowy

    CREATE TABLE ksiazka (
        id_ksiazki     integer GENERATED ALWAYS AS IDENTITY CONSTRAINT pk_ksiazka PRIMARY KEY,
        isbn           char(13)     NOT NULL CONSTRAINT uq_ksiazka_isbn UNIQUE
                                    CONSTRAINT ck_ksiazka_isbn CHECK (isbn ~ '^97[89][0-9]{10}$'),
        tytul          varchar(200) NOT NULL,
        rok_wydania    smallint     CONSTRAINT ck_ksiazka_rok CHECK (rok_wydania BETWEEN 1450 AND 2100),
        liczba_stron   smallint     CONSTRAINT ck_ksiazka_strony CHECK (liczba_stron > 0),
        id_wydawnictwa smallint     CONSTRAINT fk_ksiazka_wydawnictwo
                                    REFERENCES wydawnictwo (id_wydawnictwa) ON DELETE SET NULL
    );

    CREATE TABLE autor (
        id_autora integer GENERATED ALWAYS AS IDENTITY CONSTRAINT pk_autor PRIMARY KEY,
        imie      varchar(40) NOT NULL,
        nazwisko  varchar(60) NOT NULL
    );

  GENERATED ALWAYS AS IDENTITY – system nadaje kolejne numery; próba
  wpisania własnej wartości kończy się błędem. GENERATED BY DEFAULT AS
  IDENTITY pozwala podać wartość ręcznie. Typ serial to starszy
  odpowiednik – w nowych tabelach używaj IDENTITY.

  REFERENCES wydawnictwo bez listy kolumn wskazuje klucz główny tabeli
  wydawnictwo.

  Operator ~ dopasowuje wyrażenie regularne:
    ^ i $     początek i koniec tekstu
    [0-9]     jedna cyfra          [A-Z]   jedna wielka litera
    {10}      dokładnie 10 razy    [89]    znak 8 lub 9


4.3. Tabela łącząca (wiele do wielu) – klucz główny złożony,
     klucze obce tablicowe, UNIQUE na dwóch kolumnach

    CREATE TABLE ksiazka_autor (
        id_ksiazki integer  NOT NULL,
        id_autora  integer  NOT NULL,
        kolejnosc  smallint NOT NULL DEFAULT 1 CONSTRAINT ck_ka_kolejnosc CHECK (kolejnosc >= 1),
        CONSTRAINT pk_ksiazka_autor PRIMARY KEY (id_ksiazki, id_autora),
        CONSTRAINT fk_ka_ksiazka FOREIGN KEY (id_ksiazki)
                   REFERENCES ksiazka (id_ksiazki) ON DELETE CASCADE,
        CONSTRAINT fk_ka_autor   FOREIGN KEY (id_autora)
                   REFERENCES autor (id_autora)    ON DELETE RESTRICT,
        CONSTRAINT uq_ka_kolejnosc UNIQUE (id_ksiazki, kolejnosc)
    );


4.4. Klucz złożony w tabeli nadrzędnej i złożony klucz obcy

Numer regału jest unikalny tylko w obrębie sali, więc kluczem jest
para (sala, nr_regalu). Tabela egzemplarz odwołuje się do tej pary
złożonym kluczem obcym – liczba, kolejność i typy kolumn muszą się
zgadzać.

    CREATE TABLE regal (
        sala      char(1)  NOT NULL CONSTRAINT ck_regal_sala CHECK (sala IN ('A','B','C')),
        nr_regalu smallint NOT NULL CONSTRAINT ck_regal_nr CHECK (nr_regalu BETWEEN 1 AND 99),
        opis      varchar(60),
        CONSTRAINT pk_regal PRIMARY KEY (sala, nr_regalu)
    );

    CREATE TABLE egzemplarz (
        sygnatura  varchar(12) CONSTRAINT pk_egzemplarz PRIMARY KEY,
        id_ksiazki integer     NOT NULL CONSTRAINT fk_egz_ksiazka REFERENCES ksiazka,
        sala       char(1),
        nr_regalu  smallint,
        stan       varchar(10) NOT NULL DEFAULT 'dobry'
                   CONSTRAINT ck_egz_stan CHECK (stan IN ('nowy','dobry','zniszczony','wycofany')),
        CONSTRAINT fk_egz_regal FOREIGN KEY (sala, nr_regalu) REFERENCES regal (sala, nr_regalu),
        CONSTRAINT ck_egz_miejsce CHECK ((sala IS NULL) = (nr_regalu IS NULL))
    );

  Złożony klucz obcy z wartością NULL (domyślny tryb MATCH SIMPLE):
  jeśli choć jedna kolumna klucza obcego jest NULL, więz nie jest
  sprawdzany. Egzemplarz bez sali i regału (np. w introligatorni)
  jest więc dozwolony. Warunek ck_egz_miejsce pilnuje, by obie kolumny
  były wypełnione albo obie puste – inaczej egzemplarz z samą salą
  „przeszedłby” klucz obcy bez sprawdzenia.

  Wyrażenie (x IS NULL) = (y IS NULL) porównuje dwie wartości logiczne:
  jest prawdziwe, gdy obie kolumny są puste albo obie wypełnione.


4.5. CHECK porównujący kolumny, wartości domyślne z funkcji,
     kolumna generowana (wirtualna)

    CREATE TABLE czytelnik (
        id_czytelnika integer GENERATED ALWAYS AS IDENTITY CONSTRAINT pk_czytelnik PRIMARY KEY,
        nr_karty      char(8)     NOT NULL CONSTRAINT uq_czytelnik_karta UNIQUE
                                  CONSTRAINT ck_czytelnik_karta CHECK (nr_karty ~ '^BL[0-9]{6}$'),
        imie          varchar(40) NOT NULL,
        nazwisko      varchar(60) NOT NULL,
        kategoria     varchar(10) NOT NULL DEFAULT 'student'
                      CONSTRAINT ck_czytelnik_kat CHECK (kategoria IN ('student','pracownik','gość')),
        data_zapisu   date        NOT NULL DEFAULT current_date,
        data_waznosci date,
        CONSTRAINT ck_czytelnik_daty CHECK (data_waznosci IS NULL OR data_waznosci > data_zapisu)
    );

    CREATE TABLE wypozyczenie (
        id_wypozyczenia   integer GENERATED ALWAYS AS IDENTITY CONSTRAINT pk_wypozyczenie PRIMARY KEY,
        id_czytelnika     integer     NOT NULL CONSTRAINT fk_wyp_czytelnik
                                      REFERENCES czytelnik ON DELETE RESTRICT,
        sygnatura         varchar(12) NOT NULL CONSTRAINT fk_wyp_egzemplarz
                                      REFERENCES egzemplarz ON UPDATE CASCADE,
        data_wypozyczenia date        NOT NULL DEFAULT current_date,
        termin_zwrotu     date        NOT NULL,
        data_zwrotu       date,
        dni_wypozyczenia  integer GENERATED ALWAYS AS (data_zwrotu - data_wypozyczenia) VIRTUAL,
        CONSTRAINT ck_wyp_termin CHECK (termin_zwrotu BETWEEN data_wypozyczenia
                                                         AND data_wypozyczenia + 90),
        CONSTRAINT ck_wyp_zwrot  CHECK (data_zwrotu IS NULL OR data_zwrotu >= data_wypozyczenia)
    );

  Kolumna generowana jest wyliczana z innych kolumn tego samego
  wiersza. W PostgreSQL 18:
    VIRTUAL  (domyślnie od wersji 18) – wartość liczona przy odczycie,
             nie zajmuje miejsca,
    STORED   – wartość liczona przy zapisie i przechowywana.
  Wyrażenie może używać tylko funkcji niezmiennych (np. nie
  current_date). Do kolumny generowanej nie wolno wpisywać wartości.

  CHECK a NULL: warunek CHECK odrzuca wiersz tylko wtedy, gdy wynik
  jest FAŁSZEM. Wynik NULL (np. porównanie z pustą kolumną) przepuszcza
  wiersz. Dlatego zapis „data_zwrotu IS NULL OR ...” jest czytelniejszy,
  a kolumna wymagana potrzebuje osobnego NOT NULL.


4.6. Akcje kluczy obcych

  Akcja         Gdy usuwasz/zmieniasz wiersz nadrzędny
  ------------  --------------------------------------------------------
  NO ACTION     błąd, jeśli są wiersze podrzędne (domyślna akcja;
                sprawdzenie na końcu polecenia)
  RESTRICT      błąd, jeśli są wiersze podrzędne (sprawdzenie
                natychmiastowe)
  CASCADE       usuwa (ON DELETE) lub zmienia (ON UPDATE) wiersze
                podrzędne
  SET NULL      wpisuje NULL do kolumn klucza obcego
  SET DEFAULT   wpisuje wartość domyślną kolumny

  Akcję podajesz osobno dla usuwania i zmiany klucza:
    REFERENCES egzemplarz ON DELETE RESTRICT ON UPDATE CASCADE


5. INSERT INTO – WPROWADZANIE POJEDYNCZYCH WIERSZY
----------------------------------------------------------------------

5.1. Postacie polecenia

    -- bez listy kolumn: wartości dla WSZYSTKICH kolumn, w kolejności z CREATE TABLE
    INSERT INTO wydawnictwo VALUES (1, 'Wydawnictwo Politechniki Lubelskiej', 'PL');

    -- z listą kolumn (zalecane): pominięte kolumny dostają DEFAULT albo NULL
    INSERT INTO wydawnictwo (id_wydawnictwa, nazwa) VALUES (2, 'Helion');

    -- apostrof w tekście zapisujesz podwójnie
    INSERT INTO wydawnictwo (id_wydawnictwa, nazwa, kraj) VALUES (3, 'O''Reilly Media', 'US');

    -- identyfikator nadaje system; RETURNING zwraca nadaną wartość
    INSERT INTO ksiazka (isbn, tytul, rok_wydania, liczba_stron, id_wydawnictwa)
    VALUES ('9788328341234', 'PostgreSQL od podstaw', 2024, 412, 2)
    RETURNING id_ksiazki;

     id_ksiazki
    ------------
              1

    -- słowo DEFAULT zamiast wartości
    INSERT INTO wypozyczenie (id_czytelnika, sygnatura, data_wypozyczenia, termin_zwrotu)
    VALUES (2, 'INF-0002', DEFAULT, current_date + 30);

    -- NULL wpisujesz jawnie albo pomijasz kolumnę na liście
    INSERT INTO egzemplarz (sygnatura, id_ksiazki, sala, nr_regalu) VALUES ('INF-0003', 2, NULL, NULL);


5.2. Zapis wartości

  Typ          Przykład                 Uwagi
  -----------  -----------------------  ------------------------------
  tekst        'Kamil'                  apostrofy, nie cudzysłów
  data         '2026-10-01'             format RRRR-MM-DD
  czas         '08:30'                  format GG:MM[:SS]
  liczba       412, 150.00              kropka dziesiętna, bez apostrofów
  zakres       '[2026-12-10 10:00, 2026-12-10 12:00)'
                                        [ domknięty, ) otwarty koniec
  brak danych  NULL                     bez apostrofów; 'NULL' to tekst


5.3. Kolejność wprowadzania danych

Najpierw tabele, do których nikt się nie odwołuje kluczem obcym
(słownikowe, nadrzędne), potem tabele podrzędne. W przykładzie:

  wydawnictwo -> ksiazka -> autor -> ksiazka_autor -> regal
  -> egzemplarz -> czytelnik -> wypozyczenie


5.4. Sprawdzenie wyniku – kolumna generowana

    SELECT id_wypozyczenia, sygnatura, data_wypozyczenia, data_zwrotu, dni_wypozyczenia
    FROM wypozyczenie;

     id_wypozyczenia | sygnatura | data_wypozyczenia | data_zwrotu | dni_wypozyczenia
    -----------------+-----------+-------------------+-------------+------------------
                   1 | INF-0001  | 2026-10-01        | 2026-10-20  |               19
                   2 | INF-0002  | 2026-11-12        |             |


6. KOMUNIKATY O NARUSZENIU WIĘZÓW
----------------------------------------------------------------------

Każdy komunikat podaje nazwę więzu i wartości, które go naruszyły.

  CHECK ze wzorcem
    INSERT INTO ksiazka (isbn, tytul) VALUES ('1234567890123', 'Zły ISBN');
    ERROR:  new row for relation "ksiazka" violates check constraint "ck_ksiazka_isbn"

  UNIQUE
    INSERT INTO ksiazka (isbn, tytul) VALUES ('9788328341234', 'Duplikat');
    ERROR:  duplicate key value violates unique constraint "uq_ksiazka_isbn"
    DETAIL:  Key (isbn)=(9788328341234) already exists.

  Klucz główny złożony
    INSERT INTO ksiazka_autor (id_ksiazki, id_autora) VALUES (1, 2);
    ERROR:  duplicate key value violates unique constraint "pk_ksiazka_autor"
    DETAIL:  Key (id_ksiazki, id_autora)=(1, 2) already exists.

  Klucz obcy
    INSERT INTO ksiazka_autor (id_ksiazki, id_autora) VALUES (99, 1);
    ERROR:  insert or update on table "ksiazka_autor" violates foreign key constraint "fk_ka_ksiazka"
    DETAIL:  Key (id_ksiazki)=(99) is not present in table "ksiazka".

  Złożony klucz obcy
    INSERT INTO egzemplarz (sygnatura, id_ksiazki, sala, nr_regalu) VALUES ('INF-0009', 1, 'C', 5);
    ERROR:  insert or update on table "egzemplarz" violates foreign key constraint "fk_egz_regal"
    DETAIL:  Key (sala, nr_regalu)=(C, 5) is not present in table "regal".

  CHECK tablicowy
    INSERT INTO egzemplarz (sygnatura, id_ksiazki, sala) VALUES ('INF-0010', 1, 'A');
    ERROR:  new row for relation "egzemplarz" violates check constraint "ck_egz_miejsce"
    DETAIL:  Failing row contains (INF-0010, 1, A, null, dobry).

  CHECK z listą wartości
    INSERT INTO czytelnik (nr_karty, imie, nazwisko, kategoria) VALUES ('BL000103', 'Ola', 'Kos', 'emeryt');
    ERROR:  new row for relation "czytelnik" violates check constraint "ck_czytelnik_kat"

  NOT NULL
    INSERT INTO czytelnik (nr_karty, imie) VALUES ('BL000104', 'Ola');
    ERROR:  null value in column "nazwisko" of relation "czytelnik" violates not-null constraint

  CHECK porównujący daty
    INSERT INTO wypozyczenie (id_czytelnika, sygnatura, data_wypozyczenia, termin_zwrotu)
    VALUES (1, 'INF-0003', '2026-11-01', '2026-10-01');
    ERROR:  new row for relation "wypozyczenie" violates check constraint "ck_wyp_termin"

  Kolumna tożsamości GENERATED ALWAYS
    INSERT INTO autor (id_autora, imie, nazwisko) VALUES (100, 'Test', 'Testowy');
    ERROR:  cannot insert a non-DEFAULT value into column "id_autora"
    DETAIL:  Column "id_autora" is an identity column defined as GENERATED ALWAYS.
    HINT:  Use OVERRIDING SYSTEM VALUE to override.

  Usunięcie wiersza nadrzędnego – RESTRICT
    DELETE FROM autor WHERE id_autora = 2;
    ERROR:  update or delete on table "autor" violates RESTRICT setting of foreign key
            constraint "fk_ka_autor" on table "ksiazka_autor"
    DETAIL:  Key (id_autora)=(2) is referenced from table "ksiazka_autor".

  Usunięcie wiersza nadrzędnego – NO ACTION (akcja domyślna)
    DELETE FROM ksiazka WHERE id_ksiazki = 1;
    ERROR:  update or delete on table "ksiazka" violates foreign key constraint
            "fk_egz_ksiazka" on table "egzemplarz"
    DETAIL:  Key (id_ksiazki)=(1) is still referenced from table "egzemplarz".

  Luki w numeracji: nieudany INSERT też pobiera kolejny numer
  z sekwencji kolumny tożsamości. Numery nie wracają, więc po błędach
  kolejny poprawny wiersz dostanie np. id 5 zamiast 3. To normalne
  zachowanie, a nie błąd.


7. DZIAŁANIA KASKADOWE, TRANSAKCJE, CZYSZCZENIE TABEL
----------------------------------------------------------------------

7.1. Efekt ON DELETE SET NULL i ON UPDATE CASCADE

    DELETE FROM wydawnictwo WHERE id_wydawnictwa = 3;
    SELECT id_ksiazki, tytul, id_wydawnictwa FROM ksiazka;

     id_ksiazki |         tytul         | id_wydawnictwa
    ------------+-----------------------+----------------
              1 | PostgreSQL od podstaw |              2
              2 | Learning SQL          |                  <- SET NULL

    UPDATE egzemplarz SET sygnatura = 'INF-0001A' WHERE sygnatura = 'INF-0001';
    SELECT id_wypozyczenia, sygnatura FROM wypozyczenie ORDER BY 1;

     id_wypozyczenia | sygnatura
    -----------------+-----------
                   1 | INF-0001A                          <- CASCADE
                   2 | INF-0002


7.2. Test w transakcji wycofywanej

Zmiany wykonane po BEGIN można cofnąć poleceniem ROLLBACK. Przed
ROLLBACK widzisz skutki zmian (także kaskadowych), a po ROLLBACK dane
wracają do stanu sprzed BEGIN.

    BEGIN;
    DELETE FROM wypozyczenie WHERE id_czytelnika = 1;
    DELETE FROM czytelnik    WHERE id_czytelnika = 1;
    SELECT count(*) FROM czytelnik;      -- skutek widoczny w transakcji
    ROLLBACK;                            -- wszystko wraca

  Gdy w transakcji wystąpi błąd, kolejne polecenia są odrzucane:
    ERROR:  current transaction is aborted, commands ignored until end
            of transaction block
  Zakończ wtedy transakcję poleceniem ROLLBACK.


7.3. Czyszczenie tabeli z restartem numeracji

    TRUNCATE autor RESTART IDENTITY CASCADE;
    NOTICE:  truncate cascades to table "ksiazka_autor"

  TRUNCATE usuwa wszystkie wiersze, RESTART IDENTITY ustawia numerację
  od 1, a CASCADE czyści również tabele, które odwołują się do autor.
  Używaj ostrożnie – to nie jest DELETE wybranych wierszy.


8. ZMIANA WIĘZÓW W ISTNIEJĄCEJ TABELI – ALTER TABLE
----------------------------------------------------------------------

    -- dodanie więzu UNIQUE na dwóch kolumnach
    ALTER TABLE autor ADD CONSTRAINT uq_autor_imie_nazwisko UNIQUE (imie, nazwisko);

    -- dodanie CHECK bez sprawdzania istniejących wierszy, potem sprawdzenie
    ALTER TABLE ksiazka ADD CONSTRAINT ck_ksiazka_tytul CHECK (length(trim(tytul)) > 0) NOT VALID;
    ALTER TABLE ksiazka VALIDATE CONSTRAINT ck_ksiazka_tytul;

    -- dodanie klucza obcego do istniejącej tabeli (gdyby nie było go w CREATE TABLE)
    ALTER TABLE egzemplarz ADD CONSTRAINT fk_egz_regal
        FOREIGN KEY (sala, nr_regalu) REFERENCES regal (sala, nr_regalu);

    -- usunięcie więzu po nazwie
    ALTER TABLE ksiazka DROP CONSTRAINT ck_ksiazka_tytul;

    -- NOT NULL dodawany i usuwany przez ALTER COLUMN
    ALTER TABLE ksiazka ALTER COLUMN liczba_stron SET NOT NULL;
    ERROR:  column "liczba_stron" of relation "ksiazka" contains null values
    ALTER TABLE ksiazka ALTER COLUMN liczba_stron DROP NOT NULL;

  Więzu nie da się dodać, jeśli istniejące dane go naruszają – trzeba
  najpierw poprawić dane albo użyć NOT VALID.


9. PRZEGLĄD WIĘZÓW
----------------------------------------------------------------------

W psql: \d nazwa_tabeli pokazuje kolumny, wartości domyślne, indeksy,
więzy CHECK, klucze obce oraz tabele, które się do niej odwołują
(sekcja Referenced by).

Zapytanie do katalogu systemowego:

    SELECT conname, contype, pg_get_constraintdef(oid)
    FROM   pg_constraint
    WHERE  conrelid = 'katalog.ksiazka_autor'::regclass
    ORDER  BY contype, conname;

                  conname              | contype |                   pg_get_constraintdef
    -----------------------------------+---------+----------------------------------------------------------
     ck_ka_kolejnosc                   | c       | CHECK ((kolejnosc >= 1))
     fk_ka_autor                       | f       | FOREIGN KEY (id_autora) REFERENCES autor(id_autora) ON DELETE RESTRICT
     fk_ka_ksiazka                     | f       | FOREIGN KEY (id_ksiazki) REFERENCES ksiazka(id_ksiazki) ON DELETE CASCADE
     ksiazka_autor_id_autora_not_null  | n       | NOT NULL id_autora
     ksiazka_autor_id_ksiazki_not_null | n       | NOT NULL id_ksiazki
     ksiazka_autor_kolejnosc_not_null  | n       | NOT NULL kolejnosc
     pk_ksiazka_autor                  | p       | PRIMARY KEY (id_ksiazki, id_autora)
     uq_ka_kolejnosc                   | u       | UNIQUE (id_ksiazki, kolejnosc)

  contype: p – klucz główny, f – klucz obcy, u – UNIQUE, c – CHECK,
  n – NOT NULL, x – wykluczenie (exclusion).
  Nowość PostgreSQL 18: więzy NOT NULL są zapisywane w pg_constraint
  jako osobne więzy (typ n) z nazwami nadanymi automatycznie.
  Można też nadać im własną nazwę: kolumna typ CONSTRAINT nazwa NOT NULL.

Zapytanie zgodne ze standardem SQL:

    SELECT constraint_name, constraint_type
    FROM   information_schema.table_constraints
    WHERE  table_schema = 'katalog' AND table_name = 'egzemplarz'
    ORDER  BY 2, 1;


10. POSTGRESQL 18 – KLUCZ BEZ NAKŁADANIA SIĘ OKRESÓW (WITHOUT OVERLAPS)
----------------------------------------------------------------------

Klucz główny lub UNIQUE może zawierać kolumnę zakresu z dopiskiem
WITHOUT OVERLAPS. Wtedy dla tych samych wartości pozostałych kolumn
zakresy nie mogą się nakładać. Wymaga rozszerzenia btree_gist
(właściciel bazy może je zainstalować).

    CREATE EXTENSION IF NOT EXISTS btree_gist;

    CREATE TABLE rezerwacja_sali (
        nr_sali smallint    NOT NULL,
        okres   tsrange     NOT NULL,
        cel     varchar(60) NOT NULL,
        CONSTRAINT pk_rezerwacja PRIMARY KEY (nr_sali, okres WITHOUT OVERLAPS)
    );

    INSERT INTO rezerwacja_sali VALUES (1, '[2026-12-10 10:00, 2026-12-10 12:00)', 'zajęcia');
    INSERT INTO rezerwacja_sali VALUES (1, '[2026-12-10 12:00, 2026-12-10 14:00)', 'konsultacje');  -- OK, styka się
    INSERT INTO rezerwacja_sali VALUES (1, '[2026-12-10 11:00, 2026-12-10 13:00)', 'kolizja');

    ERROR:  conflicting key value violates exclusion constraint "pk_rezerwacja"
    DETAIL:  Key (nr_sali, okres)=(1, ["2026-12-10 11:00:00","2026-12-10 13:00:00"))
             conflicts with existing key (nr_sali, okres)=(1, ["2026-12-10 10:00:00","2026-12-10 12:00:00")).

  Typy zakresów: int4range, numrange, daterange, tsrange (data i czas),
  tstzrange (data i czas ze strefą).


11. ŚCIĄGA
----------------------------------------------------------------------

  Klucz główny kolumnowy    kol typ CONSTRAINT pk_t PRIMARY KEY
  Klucz główny złożony      CONSTRAINT pk_t PRIMARY KEY (k1, k2)
  Klucz nadawany przez SZBD kol integer GENERATED ALWAYS AS IDENTITY
  Klucz obcy kolumnowy      kol typ CONSTRAINT fk_t_x REFERENCES x [ON DELETE ...]
  Klucz obcy złożony        CONSTRAINT fk_t_x FOREIGN KEY (a, b) REFERENCES x (a, b)
  Wymagane                  kol typ NOT NULL
  Unikalne                  CONSTRAINT uq_t_k UNIQUE (k [, k2])
  Lista wartości            CHECK (kol IN ('a','b','c'))
  Zakres                    CHECK (kol BETWEEN 1 AND 5)
  Wzorzec                   CHECK (kol ~ '^[0-9]{4}$')
  Warunek na kilku kol.     CONSTRAINT ck_t_x CHECK (b > a)
  Jedno z dwóch wymagane    CHECK (a IS NOT NULL OR b IS NOT NULL)
  Oba albo żadne            CHECK ((a IS NULL) = (b IS NULL))
  Wartość domyślna          kol typ DEFAULT wartość
  Kolumna wyliczana         kol typ GENERATED ALWAYS AS (wyrażenie) [VIRTUAL|STORED]
  Okresy bez nakładania     PRIMARY KEY (k, okres WITHOUT OVERLAPS)
  Wstawienie wiersza        INSERT INTO t (k1, k2) VALUES (w1, w2) [RETURNING k];
  Test bez utraty danych    BEGIN; ... ROLLBACK;
  Wyczyszczenie tabeli      TRUNCATE t RESTART IDENTITY [CASCADE];
  Przegląd więzów           \d t   |   SELECT ... FROM pg_constraint ...
